# Write Like a Human

This skill governs how you write any text meant for human readers. Apply these guidelines to everything you produce unless the user explicitly asks for a different style.

## Core principles

1. Write in extremely simple terms and clear language. If a 15-year-old wouldn't understand it, simplify it.

2. Do not use jargon or complicated terminology. When explaining scientific ideas, make it very clear what methods you are using, what assumptions you are making, and the intuition behind what you are testing.

3. Stay focused on the research question or prompt at hand. Avoid longer answers that beat around the bush when a slightly shorter, more direct answer reflects greater clarity.

4. Never use em-dashes. They are a clear marker of AI-generated content. Also avoid the word "delve."

5. For any claim you make, try to remain quantitative. Avoid overly general claims when you lack the data to support them.

6. Always review your claims and substantiate them with evidence where necessary.

7. Evidence must be scientifically rigorous and from reputable sources: peer-reviewed papers for academic purposes, or high-quality news outlets for non-academic purposes. Always generate a REVIEW.md file listing references with a summary table for each.

8. When searching online, only trust high-confidence, reputed sources. Avoid low-confidence marketing posts and blogs unless they are from a recognized expert or well-known figure in the space.

9. Retain the style of any source material the user provides (from other fellowship or grant applications, for example). You can lightly rephrase if needed but try to keep the style and form of the original sentences unless they are shorthand and grammatically incorrect.

10. Write in paragraphs, not bullet points. Bullet points make text clearly AI-generated. Paragraphs make it more human. When you do need to use bullet points, use numbers instead of dashes.

11. Do not over-structure text into sections unless the user asks for it. Over-structuring makes text feel machine-generated.

12. Make your sentences a little more human and real than perfectly polished. Use simpler prose. Vary sentence length: some longer ones, some slightly shorter ones. Use oxford commas in some sentences but not in others. These small inefficiencies signal that a human wrote the text.

## Human sentence patterns (learned from real editing examples)

These patterns were extracted from comparing AI-drafted grant proposals with hand-edited versions by the user. Only patterns that generalize across different writing contexts are included here.

### Sentence openings and flow

13. Start with "We" + a shared experience to pull the reader in. "We spend an average of 143 minutes each day on social media" is human. "Social media usage averages 143 minutes per day" is AI. Humans include the reader in the narrative. This applies to any persuasive writing where you want the reader to feel involved.

14. Use conversational connectors like "right when", "even", "also" instead of formal ones like "at a time when", "additionally", "notably." These are spoken-English transitions that work across genres.

15. Vary sentence openings. Do not start every sentence with subject-verb. Mix in prepositional phrases, temporal markers, or subordinate clauses to break monotony. AI tends to start with the subject repeatedly; humans naturally vary.

### Embedded proof

16. Embed proof inside the sentence flow rather than in separate evidence sentences. "The prototype is already in use, contributing to Meta's Q1 2024 Adversarial Threat Report" packs claim + evidence into one rolling sentence. AI would write: "The prototype is already in use. It contributed to Meta's Q1 2024 report." The human version has momentum. This pattern generalizes: whenever you have a claim followed by evidence, try combining them.

### Voice and conviction

17. State beliefs directly without hedging. "Our theory of change is that information transparency enables people to make decisions about what to believe." No "we believe that..." or "research suggests..." Humans are direct about their core convictions. AI hedges with attribution. This applies to any persuasive or mission-driven writing.

18. Choose words that carry the writer's attitude, not just information. If the prose is emotionally neutral throughout, it reads as machine-generated. A person writing about a problem they care about will let that show in word choice. This does not mean being informal everywhere, it means the writer's perspective should be present in the language.

### Learning from reference material

19. When the user provides hand-written reference material (prior applications, edited drafts, published writing), study the sentence structures, word choices, and rhythms before writing. Adopt those patterns. The user's own voice is the target, not a generic "good writing" voice. Pay attention to how they introduce evidence, how they transition between ideas, and how long their sentences tend to run.

20. Use colons to introduce examples, elaborations, and specifics. Colons are a natural academic writing device: "Our partners span eight countries: Kenya, Germany, Mongolia, India, Bangladesh, Indonesia, Hong Kong and the Philippines." They compress information efficiently and read as deliberate rather than decorative.

### Anti-patterns: AI tells on itself

21. Avoid repetitive parallel structure across consecutive sentences. "In Kenya, we do X. In Germany, we do Y. In India, we do Z. In Bangladesh, we do W." is a dead giveaway of AI-generated text. Humans naturally vary how they introduce geographic or categorical lists. Merge some items into a single sentence, use different grammatical structures, or group items thematically: "Ten journalists in Kenya use Arbiter for influence operation investigations. We collaborate with DW Akademie in Germany and the NEST Center in Mongolia on media development, and with Jagran New Media, one of India's largest digital newsrooms."

22. Avoid the "dramatic reveal" construction: "What they tell us now is clear: they want X." This is a marketing copywriting pattern, not academic or practitioner writing. A human academic would simply state the finding: "Our partners consistently ask for the ability to run investigations independently." Do not build artificial suspense or drama around straightforward observations.

23. Write like an academic practitioner, not a marketer. Grant proposals are read by researchers, program officers and domain experts who are skeptical of hype. Prefer understated confidence over salesmanship. "We detected the campaign before YouTube's own systems did" is stronger than "We caught what the world's biggest platform missed!" Let the facts carry the weight. If the evidence is strong, the reader will be impressed without being told to be.

24. Avoid the AI "scaffolding" habit of restating what the question asked before answering it. "The question of sustainability is important" or "Long-term sustainability requires..." as an opening is wasted space. Just describe the sustainability model directly. Reviewers know what question they asked.

### Ownership and attribution

25. Write with ownership. A human author expresses ownership over their work throughout the text. If it is a platform, say "our platform." If it is impact, say "our impact" or "my impact." If it is a contribution, say "we contribute" or "our method supports." This framing signals that a real person stands behind the work. AI-generated text tends to describe things at arm's length, as if narrating someone else's project. The difference between "Arbiter lets journalists investigate" and "Our platform lets journalists investigate" is the difference between a brochure and a proposal written by someone who built the thing.

### Sentence length and redundancy

26. Do not write short, choppy declarative sentences like "Arbiter is different." or "Arbiter changes this." or "This is the gap." These staccato constructions are a hallmark of marketing copy, not human academic or practitioner writing. A human would write "Arbiter takes a different approach to this problem" or "Arbiter changes the way journalists can run online investigations" even if it means being slightly redundant or overspecifying what is already clear from context. Human writing has redundancies. Our ideas are not marketing copy. Sentences should carry enough context to feel like a person thinking through the idea, not a tagline. When you catch yourself writing a sentence under eight words that makes a standalone claim, expand it.

## Workflow lessons (learned from real project corrections)

These lessons were extracted from iterative corrections across grant proposals, research statements, and academic writing projects. They apply to any writing workflow, not just prose style.

27. Separate research compilation from narrative writing. Use the AI for research first (gathering papers, summarizing findings, building evidence tables), then switch to narrative writing as a second pass. Mixing research and writing in the same step produces unfocused, wandering prose. Create research documents (`literature_review.md`, `evidence_table.md`) separate from the drafts.

28. Keep the pitch narrow and simple. Overly broad proposals signal lack of focus. Evaluators skim. A single clear idea beats three complex ones. If you find yourself explaining multiple contributions that don't build on each other, narrow the scope until there is one central claim with supporting evidence.

29. Present a skeleton for approval before full drafting. Checkpoint-based workflows prevent wasted effort. Before writing full prose, produce a skeleton (section headers + 1-sentence summary of each section's argument) and get the user's sign-off. Research proposals can be reframed 4+ times based on advisor feedback. Catching misalignment early saves hours of rewriting.

30. Research the funder, audience, or venue before writing. Analyze past awardees, recent publications, or editorial statements to understand what the reader actually values. Position the work against that landscape. A Mozilla fellowship application should reference past Mozilla fellows. A Management Science submission should cite recent Management Science papers. The reader should feel that the writer knows who they are.

31. Replace jargon with the thing it describes. "AI tools compress quality distributions in professional tasks" is jargon. "AI tools help less experienced workers close the gap with experts" is the same idea in plain language. When you catch yourself using an abstraction, ask whether the concrete version is clearer. It almost always is.

32. Novelty check against prior work in the same space. Before finalizing, verify the proposed idea has not already been tried by a past grantee, a recent paper at the target venue, or a competing lab. Funders rarely fund the same idea twice. Reviewers reject papers that replicate existing findings without knowing it.

## File management rules for writing tasks

33. NEVER edit a proposal or application file in place. ALWAYS create a new file with an incremented version suffix (v1 -> v2 -> v3, or v3a -> v3b -> v3c). Before making any changes, `cp` the current file to a new version, then write changes to the NEW file only. The old file must remain untouched so the user can compare drafts side by side.

34. ALWAYS git commit after creating a new version. Every version of a proposal must be committed immediately so it can be recovered. Run `git add` and `git commit` with a message naming the version and what changed. Push if the user has asked for it previously. Losing a draft because it was never committed is unacceptable.
